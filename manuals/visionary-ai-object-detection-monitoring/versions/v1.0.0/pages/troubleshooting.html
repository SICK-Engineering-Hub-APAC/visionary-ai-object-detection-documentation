Troubleshooting

Start with the symptom in the table, then use the referenced pages and Log Monitoring for precise error details. Most issues can be diagnosed without modifying device scripts.

Symptoms and actions

Symptom Likely cause / recommended action
No camera image or camera disconnected Check device power, Ethernet reachability and the camera status. Confirm monitoring is enabled; review Camera acquisition settings, reload when appropriate and check Log Monitoring.
Application shows not ready Allow startup to finish, confirm a healthy camera and app in status, then reload once if a pending configuration change exists. Investigate logs if status remains unavailable.
Live preview is delayed or stale Check connection and camera workload. Try a longer browser polling interval or lower preview width/JPEG quality. Verify stale/request timeout settings.
Image shows objects but no boxes Check that the correct compatible model is uploaded, enabled, and actually running. Reload after model changes; verify DNN license. Test lighting and threshold.
Too many duplicate overlapping boxes Review Object Detection NMS strategy and threshold; verify that model outputs and classes are correct.
Objects appear slowly Check recognition time (a nonzero value delays confirmation), detection cycle time, and the model’s inference processing load.
A missing object remains counted Check holding time. Temporarily lost tracks may remain as held boxes at their last known position until the holding window expires.
Object quantity does not match a production counter Quantities are current scene detections, not accumulated pass counts; use a separate edge/business counting algorithm for event totals.
Configuration not applied after Save Watch for reloadRequired and reload the app. Image-collection settings are the main exception and apply immediately.
Optimized settings import fails Ensure all three referenced network files exist on the camera with exact model IDs, including disabled models. Stop timed collection and check the import error.
Model upload fails Ensure it is a SICK AppSpace-compatible network JSON file, not ONNX or an arbitrary JSON. Check file size/storage limit and read the validation message.
Stop monitoring button fails Timed automatic collection or a pending manual capture can block stop. Finish/stop the capture session first.
Automatic image collection does not start Confirm camera connected, reasonable interval/max count, free device storage and no conflicting operation. Check collection event/error.
Downloaded ZIP unavailable Download soon after preparation and use the exact returned device path. Acknowledge the downloaded temporary ZIP to clear it.
MQTT has no messages Ensure MQTT enabled, correct broker host/port/topic and credentials, unique client ID, correct TLS setting and active model inference. Check Log Monitoring.
License warning / trial expired Activate SICK Deep Learning Classification part no. 1614850 using LicenseManager, verify the feature on the correct camera, then reload and retest.
External REST call returns error Check the endpoint, function name, POST method and JSON body wrapper; inspect both header.status and data.success / message.
Device reboots or app restarts Persisted settings and stop preference restore at startup, but preview and external event subscriptions must reconnect. Check configuration revision and active models.

A structured troubleshooting process

  1. Record the symptom: note camera identity, time, current page, app version (1.0.0) and whether monitoring is on or stopped.
  2. Check the basics: network, power, camera connected, App ready, enabled model, DNN license, and reload-required flag.
  3. Reproduce safely: present a known test object, or run the relevant UI function once under controlled conditions.
  4. Capture evidence: relevant Log Monitoring entries, screenshot, REST getStatus, settings export and model IDs if support requests them. Sanitize passwords and tickets.
  5. Change one variable: adjust the most relevant setting, Save and Reload when required; compare the same test scene.
  6. Escalate: if not resolved, give SICK the observed behavior, date/time, logs, firmware, camera type and steps already tested.

Common API error codes

Message Meaning
backup_model_file_missing Settings import references a model whose actual file does not exist on this device.
reload_required Operation saved successfully and requires reload to apply.
collection_busy / collection_active A timed collection or pending capture conflicts with the requested operation.
threshold_out_of_range Model confidence threshold must be between 0 and 1.
invalid_recognition_timing Recognition or holding time is not a valid integer in the supported 0–600,000 ms range.
unsupported_network_model / invalid_model_json Uploaded model file is incompatible or malformed.
camera_unavailable Capture cannot be started because camera resources are unavailable.

Routine care

Before changing models or settings, export a backup. Keep the optical window clean, stable and correctly aimed; check detection with a known target after process/layout changes. Manage captured images on the camera to preserve storage; monitor logs and MQTT connectivity. Re-verify license state and model load after firmware or application maintenance.
