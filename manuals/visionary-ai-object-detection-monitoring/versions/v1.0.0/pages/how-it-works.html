Concepts & behavior

How the System Works

The application executes directly on the SICK Visionary B-Two device. Detection processing does not require a cloud server or an external PC.

Detection workflow

Visionary B-Two image→Frame sampling→Active model inference→Confidence + overlap filtering→Recognition / holding→Web UI + events / MQTT
Stage What happens
Camera acquisition The camera produces image frames using the configured acquisition mode and FPS. Changing FPS does not directly set the model inference rate.
Model inference At its configured detection cycle, an enabled network is fed a camera image and predicts object class, confidence and bounding rectangle.
Confidence threshold Results below that network model’s threshold are excluded; raising the threshold reduces weaker detections but may miss real objects.
NMS Non-maximum suppression removes overlapping duplicate boxes based on the chosen strategy and overlap threshold.
Temporal filtering Recognition time filters brief appearances; holding time retains last-known detections across short missed observations.
Output Live preview and current per-class quantities in the browser; detection events on Crown WebSocket and optional MQTT publication.

Network models and practical limits

A network model is a trained AppSpace-compatible .json neural network. A model may recognize one type of object or contain several classes. The camera stores model files separately from a settings backup. Only enabled models can run, and the number of simultaneously active models is limited by MAX_MODELS (the supplied optimized backup sets this to 1).

Models in the supplied optimized backup: Human (enabled, threshold 0.70, recognition 1,000 ms, holding 3,000 ms).

Recognition & holding times

Parameter Behavior
Recognition time How long the same matched detection must be seen across consecutive inference observations before it is reported. 0 disables the delay.
Holding time How long a recognized detection may remain reported after its last real observation. The box is shown dashed/faded and marked as held, at its last-known position.
Both zero Immediate results with no temporal stabilizing delay.
Tracking limits Matching is based on same-class bounding-box overlap. It does not identify a specific person, preserve identities through crossings or perform facial recognition.
Timing example: With Human recognition 1 second and holding 3 seconds, a detection must persist long enough to be recognized, and an already-recognized person can remain counted and shown as held during a short occlusion. A held box is not proof that the person is still at that location.

Preview rate versus inference rate

Three separate settings determine update behavior: Camera FPS controls image acquisition; Live preview capture and polling intervals control the browser image refresh; Detection cycle time controls the inference attempt cadence. These are independent and actual performance also depends on the device and loaded model. The inference cycle has a minimum of 1,000 ms.

What counts mean

The side panel shows how many objects are currently recognized in each model/class, including held detections. It is not a cumulative number of products, unique people, event occurrences or lifetime detections. Hiding a model or a class in the panel hides its boxes for display only; it does not disable inference or suppress transmitted results.

Monitoring, persistence & recovery

Stop saves a persistent preference and immediately stops acquisition, live preview and detection. It automatically requests application reload. Resume saves the opposite preference and automatically reloads to restart them. Both survive app reload and camera reboot. A pending capture or automatic collection can prevent stopping. Model and most settings changes require a separate application reload, indicated by a header warning.

Scope of v1.0.0

Version 1.0.0 performs 2D bounding-box detection. It does not include configured ROI/zone filtering, 3D object coordinates, depth-based positioning, durable event-history storage or unique-person re-identification. Optional depth map camera capture is not a 3D localization feature in this version.
