External systems

Integration & Data Outputs

The application processes object detection directly on the camera. External systems may consume the current state using the device Crown REST API, receive changes over Crown WebSocket, or subscribe to MQTT when it is configured and enabled.

Choose an integration route

Interface When to use
Crown REST API Request the latest application state and settings; control monitoring; manage models and image collection; download collected images. Suitable for control panels, tools and supervisory polling.
Crown WebSocket Subscribe to AIObjectDetectionMonitoring/onDetection and /onStatus events (also /onLog, /onCollection). Suitable for low-latency updates without continuous REST polling.
MQTT client Publish detection-result JSON to a configured broker/topic; typically for PLC gateways, integration services and plant systems. Requires the broker to be reachable and MQTT enabled in Settings.
Device file endpoint Download a captured PNG or prepared dataset ZIP using GET /api/crown/file?filePath=… after obtaining its path from the REST API.

Information carried by detection results

Field Purpose
modelId, modelName Identifies which loaded detection network produced the result.
timestamp, inferenceMs Time of result and inference processing duration.
detections[] The current list of recognized detections for that model; empty array means no recognized objects in that result.
label, classId Object class name and corresponding class ID.
score Confidence value, typically in the 0–1 range.
box 2D normalized bounding coordinates; interpret against the image dimensions.
trackId, held, lastSeenMs Optional temporal-tracking metadata, present when timing-based tracking is active. Held detection means a retained last-known box, not a new observation.

Important integration semantics

  • Counts represent current recognized objects, including held observations; they are not cumulative product totals or unique-person identities.
  • Detection results can arrive per model and can include empty detections. External clients should maintain state and tolerate missing/late/repeated updates.
  • REST is a request/response interface, not a subscription stream. Use Crown WebSocket or MQTT for push updates.
  • The configured inference period, preview refresh period and camera FPS are independent. Do not assume every preview frame produces a new inference.
  • Security and network access are controlled by the camera/system deployment. Protect ports, TLS, credentials and broker access as part of plant network engineering.

Typical integration flow

  1. From an integration PC, verify IP connectivity and confirm the camera UI opens.
  2. Use REST getStatus to verify the model is loaded and monitoring is running.
  3. Use REST getNetworkModels to discover configured model IDs and classes.
  4. For live updates, register on Crown WebSocket AIObjectDetectionMonitoring/onDetection or enable MQTT and subscribe to the configured topic.
  5. Map normalized boxes, classes and confidence to your external application, and treat held boxes and disconnects explicitly.
  6. Test system restart, camera disconnection, empty results, license restrictions and reconnection before production use.

See MQTT configuration for broker settings and REST API Reference for all callable functions and example requests.
